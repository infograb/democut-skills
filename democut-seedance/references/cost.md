# 비용 — 토큰 공식과 운영

## 공식

```
토큰 = duration(초) × 가로 × 세로 × 24(fps) / 1024
비용 = 토큰 × 단가 / 1,000,000
```

**완전히 결정론적이다.** 프롬프트 내용·오디오 유무와 무관하다
(실측: `generate_audio=true` 40,594 토큰 ↔ `false` 40,594 토큰, 동일).
덕분에 **제출 전에 비용을 정확히 계산할 수 있다.**

## 단가

| 경로 | $/1M 토큰 |
|---|---|
| **리소스 팩** (선불) | **4.30** |
| 종량제 480p·720p | 7.00 |
| 종량제 1080p | 7.70 |

팩이 종량제보다 **39% 싸다.** 팩은 모델을 여는 티켓이면서 동시에 할인 상품이다.

## 실측 비용표 (리소스 팩 기준)

| 사양 | 토큰 | 비용 |
|---|---|---|
| 480p 4초 | 40,594 | $0.17 |
| 720p 5초 | 108,000 | $0.46 |
| 720p 10초 | 216,000 | $0.93 |
| 1080p 10초 | 489,600 | $2.11 |
| 1080p 15초 | 734,400 | $3.16 |

## 리소스 팩 운영

- **볼륨 할인이 없다** — 7M/10M/13M 팩의 1M 단가가 전부 동일하다.
  큰 팩은 만료 위험만 늘리므로 **최소 팩부터** 산다.
- **90일 만료**, **환불 불가**
- **모델 전용** — 2.0 팩으로 2.5 를 열 수 없다
- 소진되면 자동으로 종량제로 전환된다(서비스가 끊기지는 않는다)
- 실패한 생성은 과금되지 않는다

## 추정할 때 주의

요청 해상도와 **실제 출력 픽셀이 다를 수 있다.** 실측에서 480p/16:9 요청이
864×496 으로 나왔는데 보고된 토큰을 역산하면 유효 높이가 ~501 이다.
표 값만 믿으면 약 1% 과소 추정되므로, **예산 검사에는 안전 마진(5% 권장)을 곱한다.**
과대 추정은 요청이 막히는 것으로 끝나지만, 과소 추정은 막아야 할 요청을 통과시킨다.

원장·정산에는 추정치가 아니라 응답의 `usage.completion_tokens` 를 쓴다.
