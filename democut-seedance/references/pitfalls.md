# 함정 — 실측으로 확인된 것들

## Idempotency-Key 가 없다

BytePlus 는 멱등 키를 지원하지 않는다. **같은 요청을 두 번 보내면 두 번 과금된다.**
에이전트는 실패 시 재시도하는 것이 기본 습성이므로 이것이 실질 위험이다.

- 재시도 전에 **작업 목록·상태를 먼저 조회**한다
- 제출 요청이 타임아웃되면 **접수됐을 수 있다** — 재제출 전에 확인한다
- 클라이언트에서 요청 지문(프롬프트+파라미터 해시)으로 중복을 걸러낸다

## 결과 URL 은 24시간 만료

`content.video_url` 은 서명 URL 이고 `X-Tos-Expires=86400` 이다.
**성공 즉시 내려받는다.** 만료 후에는 재생성뿐이고 그건 재과금이다.
작업 자체도 `execution_expires_after`(48시간) 후 사라진다.

## duration 하한이 4초다

3초를 요청하면 거부된다. 모델별 범위는 `models.md` 참조.
짧은 컷이 필요하면 4초로 만들고 잘라 쓴다.

## 리소스 팩 없이는 모델 활성화조차 안 된다

```
400 BadRequest: No available resource packs. Please purchase a resource pack first.
```

키 발급 → 모델 활성화 순서로 진행하면 여기서 막힌다.
**팩 구매가 활성화보다 먼저다.**

## 동시 실행 상한은 계정 유형이 정한다

| 계정 | Max RPM | 동시 실행 |
|---|---|---|
| 개인(Personal) | 180 | **3** |
| 기업(Business) | 600 | **10** |

Seedance 계열 4종 공통이며 **Organization 을 만들어도 바뀌지 않는다.**
계정 유형은 가입 시 확정되고 **나중에 변경할 수 없다** — Personal 로 가입했다면
새 계정을 만들거나 콘솔에서 상한 증액을 요청해야 한다.

실측으로 동시 4건이 즉시 `running` 으로 들어갔다(429·큐잉 없음). 서버측 병렬 처리도
양호해서 4건 동시 제출 시 마지막 완료가 121초였다(단독 90초 대비).

## generate_audio 는 비용 레버가 아니다

`false` 로 두면 오디오 트랙이 실제로 사라지고 파일 크기가 절반이 되지만
**토큰은 1개도 줄지 않는다.** 그래도 DemoCut 은 TTS 를 따로 mux 하므로
`false` 가 맞다 — 이유는 비용이 아니라 파이프라인 정합이다.

## 이미지는 공개 URL 만 받는다

로컬 파일 경로도 base64 data URI 도 받지 않는다. 그리고 `content` 에 이미지를
넣기만 하면 무시될 수 있어서 **프롬프트 본문에서 `[Image 1]` 로 명시 참조**해야 한다.
공식 예제도 *"opening frame is [Image 1]... the final frame freezes on Image 2"* 처럼 쓴다.

## 립싱크 모델이 아니다

Seedance 는 입력 오디오를 **음색·리듬 참조**로만 쓰고, 발화는 프롬프트 안 대사에서
합성한다. 나레이션 wav 에 입을 맞추는 진짜 립싱크가 필요하면 OmniHuman 1.5 를 쓴다
(별도 모델, $0.12/초).
