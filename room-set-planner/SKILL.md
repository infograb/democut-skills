# room-set-planner

방을 오늘의집 제품으로 꾸미고, **제품 실측대로** 놓은 평면도와 리뷰용 인벤토리를 만든다.

DemoCut 의 쓰임새 하나다. 숏폼을 찍을 때마다 방이 바뀌고, 그 방에 놓인 제품을 리뷰한다.
이 스킬은 「어떤 방에 무엇을 어디에 놓고, 각 제품의 무엇을 리뷰할지」를 한 장으로 만든다.
영상 제작(DemoCut 프로젝트·컷)은 이 스킬 밖이다.

## 원칙

- **실측을 모르는 제품은 놓지 않는다.** 실측 근거(`dims_source`)가 없으면 검사가 오류를 내고 배치를 막는다.
  그 제품은 사용자에게 묻거나 다른 제품을 찾는다. 치수를 짐작해 채우지 않는다.
- **사용성은 눈대중이 아니라 검사로 본다.** 놓을 때마다 `planner.py check` 를 돌리고 오류 0 이 될 때까지 고친다.
  주의는 남겨도 되지만 보고에 이유를 적는다.
- **생김새는 사용자가 사진을 보고 고른다.** 화면에 보이는 생김새가 리뷰 세트의 핵심이다. 실측·리뷰 수는 후보를 거르는 조건일
  뿐이다. 방향(색·재질·배치)은 레퍼런스 사진으로, 눈에 띄는 가구는 후보 사진 2~3개로 보여 주고 고르게 한다.
- **사지 않는다.** 장바구니·구매·로그인은 하지 않는다. 가격은 조회 시점 값이다.
- 사용자가 준 것이 먼저다: 사용자 도면 > 평면 틀, 사용자 링크 > 스킬이 찾은 제품, 사용자가 가진 가구(`owned`)는 그대로 둔다.

## 도구

스크립트는 이 스킬 디렉터리의 `scripts/` 에 있다. 표준 라이브러리만 쓴다(Python 3.8+).

```bash
P=<이 스킬 디렉터리>/scripts
python3 $P/planner.py shell spec.json -o house.json      # 평면 틀로 집 구조
python3 $P/planner.py check house.json                   # 검사 (오류가 있으면 종료 코드 1)
python3 $P/planner.py walls house.json ROOM_ID           # 벽별 빈 구간 = 가구를 붙일 자리와 최대 폭
python3 $P/planner.py inventory house.json               # 방별 인벤토리 마크다운
python3 $P/planner.py render house.json -o plan.html [--embed-images]   # plan.svg(도면만)도 함께 쓴다
python3 -I $P/ohouse_sizes.py EXTRACT.txt [--download DIR]   # 오늘의집 페이지에서 실측 후보·리뷰 정보 뽑기
python3 -I $P/refboard.py pins EXTRACT.txt... --download DIR  # 핀터레스트 페이지에서 핀 사진 받기
python3 -I $P/refboard.py sheet DIR -o OUT                    # 받은 사진을 번호 붙인 모음 시트로(Pillow 필요)
python3 -I $P/refboard.py board CHOICES.json -o board.html    # 고를 선택지를 사진과 함께 HTML 한 장으로
```

참고 문서는 필요할 때 읽는다.

## 작업 순서

### 1. 먼저 여섯 가지를 묻는다

꾸미기 전에 **집 유형(원룸·아파트 등) · 방 크기와 개수 · 예산 · 색감 · 인테리어 느낌(원목·쇠테리어 등) · 추가 요구사항**을
묻는다. 질문마다 선택지를 붙인다. 선택지와 각 답을 어디에 쓰는지는 style-research.md 「여섯 가지를 묻는다」.
사용자가 이미 말한 것은 다시 묻지 않고 「이렇게 알고 있다」 고만 적는다.

- 「이번 편 방」 「촬영 세트」 처럼 방 하나면 `type: "room"`. 현관이 필요 없다.
- 원룸형에서 주방 크기를 안 주면 기본 크기로 넣는다(원룸에도 싱크대 복도는 있다). 주방·화장실이 정말 없는 방이면 `type: "room"` 이다.
- 평수만 주면 가로·세로를 묻거나, 가정한 비율을 `meta.notes` 에 적고 진행한다. 문·창 위치를 모르면 추가 요구사항에서 묻는다.
- 예산을 받으면 house.json `budget`(원)에 적는다. 「제한 없음」이면 적지 않고 그 사실을 `meta.notes` 에 남긴다.
- 추가 요구사항에 리뷰할 제품·가진 가구(`owned`)·꼭 쓸 링크가 있으면 그것이 먼저다(원칙).

### 2. 집 구조 만들기

출력 디렉터리는 사용자가 정한 곳, 없으면 `~/room-plans/<slug>/` 다(`<slug>` 는 영문 소문자와 하이픈).
그 안에 `spec.json` · `house.json` · `plan.html` · `plan.svg` 를 둔다.

- 사용자 도면이 있으면 house.json 을 직접 쓴다(house-json.md 「사용자가 도면을 줄 때」).
- 없으면 spec.json 을 쓰고 `shell` 로 만든다. 출력의 가정(`*` 줄)을 사용자에게 전한다.
- `check` 를 돌려 구조 오류(방 겹침, 문이 벽에 없음)가 없는지 본다.

### 3. 레퍼런스를 찾아 방향을 고르게 한다

style-research.md 를 따른다. 요점:

1. 답(유형·크기·색감·느낌)으로 검색 낱말을 만든다. 추가 요구사항이 없으면 색이나 느낌을 바꾼 낱말로 방향을 둘 이상 찾는다.
2. Tavily 로 핀터레스트를 찾고(`include_domains: ["pinterest.com"]`, extract 는 한 번에 한 주소), `refboard.py pins` 로
   사진을 받아 `sheet` 로 훑는다. 우리 방과 크기·가구가 비슷한 실제 집 사진을 남긴다.
3. 남긴 사진을 방향 2~3개로 묶어 색·재질·가구 모양·배치 패턴을 적고, `refboard.py board` 로 HTML 한 장을 만든다.
4. 경로를 주고 방향을 선택지로 묻는다. 고른 방향을 house.json `meta.style` 에 적는다.

핀 사진은 보고 고르는 데만 쓴다. 사진 생성 참고 이미지나 영상에 넣지 않는다.

### 4. 배치를 구성한다

고른 방향의 배치 패턴(`meta.style.layout`)을 우리 방에 옮긴다. 레퍼런스의 배치가 이 방 크기에서 검사를 못 넘으면,
그 사실과 바꾼 점을 보고에 적는다.

용도와 리뷰 대상을 보고 방마다 품목 목록을 정한다. 침실이면 침대·협탁·옷장·조명, 작업실이면 책상·의자·수납·조명 식이다.
레퍼런스에 보이는 소품(조명·러그·선반)도 방향의 일부라 품목에 넣는다.
리뷰할 제품은 화면에 잘 보이는 자리(창 빛이 드는 쪽, 문에서 보이는 면)에 두는 것을 우선한다.

`walls house.json ROOM_ID` 로 벽마다 빈 구간을 본다. 문 열림 범위·문 앞·창이 빠진 길이가 나온다.
그 길이가 그 벽에 놓을 제품 폭의 상한이다. 큰 가구(침대·옷장·소파·책상)부터 자리를 잡는다.
제품을 정하기 전에는 `"placeholder": true` 와 표준 크기로 자리를 잡아 `check` 해 본다. 배치가 서야 제품 폭 범위가 정해진다.

예산이 있으면 품목 목록이 정해진 자리에서 **전체 예산을 품목 예산으로 나눠** `items[].budget` 에 적는다.

- 리뷰할 제품과 큰 가구(침대·옷장·책상·의자)에 먼저 많이 준다. 보유 가구(`owned`)는 0 이다.
- 합계가 전체 예산을 넘지 않게, 가격이 옵션마다 다를 것을 생각해 1할 정도 남긴다.
- 나눈 표를 사용자에게 보여 준다. 품목을 빼거나 바꿔야 예산에 맞으면 그 선택을 묻는다.
- `check` 가 「남은 예산 …원으로 고를 품목」 을 알려 준다. 고르지 않은 품목의 예산 합계가 남은 예산보다 크면 주의가 뜬다.

### 5. 오늘의집 제품 찾기와 실측 확인

ohouse-sizing.md 를 따른다. 요점:

1. Tavily search(`include_domains: ["store.ohou.se"]`, 질의 「오늘의집 쇼핑 + 품목 + 방향 낱말(`meta.style.keywords`) + 폭·용도 + 상품」)로
   후보를 찾는다. `curl`·WebFetch 는 403 이다.
2. 후보를 Tavily extract(`extract_depth: "advanced"`, `include_images: true`)로 받고, 결과를 `ohouse_sizes.py` 에 넘긴다.
   「⚠ 덜 그려진 페이지」 가 나오면 `https://ohou.se/productions/<id>/selling` 으로 다시 받는다.
3. 사이즈표 이미지를 `--download` 로 새 빈 디렉터리에 받아 `Read` 로 읽는다. 침대는 매트리스가 아니라 프레임 바깥 치수다.
4. 실측·근거·가격·평점·리뷰 수·대표 사진·특징 3~5개를 `product` 에 적는다. `checked` 에 오늘 날짜.

실측을 못 찾으면 그 제품을 버리고 다음 후보로 간다. 사용자가 고집한 제품이면 사용자에게 실측을 묻는다.

**눈에 띄는 가구는 사용자가 고른다.** 침대·책상·의자·협탁·옷장·소파·조명처럼 화면에 크게 보이는 품목은 실측·예산을
넘긴 후보 가운데 방향(`palette`·`shapes`)에 맞는 2~3개를 골라, 대표 사진으로 `refboard.py board` 를 만들어 보여 주고 묻는다.
보여 줄 사진은 **고른 옵션의 색으로 제품 전체가 보이는 사진**이어야 한다. 받아서 `Read` 로 먼저 본다. 첫 썸네일이 서랍 근접 사진이거나
다른 색 옵션인 일이 잦다(2026-11-11 협탁 후보 셋 가운데 둘이 그랬다).
작은 소품이나 안 보이는 품목은 혼자 골라도 되지만, 보고에 「생김새는 내가 골랐다」 고 적는다.

품목 예산이 있으면 검색 질의에 상한을 넣고(「10만원 이하」), `ohouse_sizes.py` 요약의 가격이 품목 예산을 넘는 후보는
실측을 보기 전에 버린다. 고를 옵션의 가격으로 판단한다(옵션마다 가격이 다르다). 예산 안에서 실측이 맞는 제품이 없으면
다른 품목 예산을 줄여 옮기거나 사용자에게 알린다. 예산을 넘는 제품을 넣고 넘어가지 않는다.

### 6. 놓고 검사하고 고치기

house.json 의 `items` 에 제품을 넣고 `check` 를 돌린다. 오류를 하나씩 고친다.

| 오류 | 고치는 법 |
|---|---|
| 겹친다 · 방 밖으로 나간다 | `offset` 을 옮기거나 다른 벽으로. 안 되면 더 작은 제품 |
| 앞 여유 · 침대 옆 여유 | 마주 보는 가구를 옮긴다. 메시지가 막는 것을 알려 준다 |
| 문이 다 열리지 않는다 | 문 열림 범위(`walls` 의 「막힘」)에서 가구를 뺀다 |
| 닿을 수 없다 | 동선을 막은 가구를 옮긴다. 「좁아진다」 주의가 병목 자리를 알려 준다 |
| 부딪친다 · 밑에 들어가지 않는다 · 받침 밖으로 떨어진다 | 물리적으로 놓일 수 없는 자리다. 의자는 책상 앞으로 빼고, 벽걸이는 높이를 바꾸고, 올려 둔 것은 받침 위로 옮긴다(house-json.md 「물리적으로 놓일 수 있나」) |
| 예산을 넘는다 · 품목 예산을 넘는다 | 그 품목을 품목 예산 안의 다른 제품으로 바꾼다. 안 되면 품목 예산을 다시 나누거나 사용자에게 품목을 뺄지 묻는다 |
| 실측 미확인 · 제품 링크 없음 | 5단계로 돌아간다 |

「통로가 약 550~750mm 로 좁아진다」 주의는 폭 3m 남짓한 원룸에 침대·책상·옷장을 다 넣으면 피하기 어렵다.
가까운 가구를 옮기거나 더 얕은 제품으로 바꿔 보고, 그래도 남으면 그대로 두고 보고에 이유를 적는다.

한 번에 하나씩 고치고 다시 검사한다. 오류가 0 이 되면 남은 주의를 읽고, 고칠 수 있으면 고친다.
예산이 있으면 오류 0 은 합계가 예산 안이라는 뜻이다. 「가격을 모르는 품목」 주의가 남아 있으면 그 품목은 판정에서 빠졌으니 가격을 채운다.

### 7. 그리기

```bash
python3 $P/planner.py render house.json -o plan.html --embed-images
```

`--embed-images` 는 제품 사진을 HTML 안에 넣어 파일 하나로 공유되게 한다(못 받은 사진은 원래 주소를 쓴다).
평면도(비울 자리·가구 앞면·문 열림), 검사 결과, 방별 인벤토리 표, **리뷰 카드**(사진·가격·평점·특징·실측)가 한 장에 나온다.
카드나 표에 마우스를 올리면 평면도에서 그 자리가 강조된다.

같은 이름의 `plan.svg` 도 함께 생긴다. 도면만 담은 흰 바탕 그림이라 이미지로 열리고, 문서·영상 컷에 그대로 넣을 수 있다.
도면에는 벽·창·문 열림 호와 가구 기호(침대 베개, 소파 등받이·팔걸이, 변기, 세면대, 장스탠드 등)가 실측 크기로 그려진다.
그린 뒤 `plan.svg` 를 열어 방 모양과 가구 자리가 의도대로인지 한 번 본다.

### 8. 보고

다음 순서로 짧게 쓴다.

1. 파일 경로(`plan.html`, `plan.svg`, `house.json`)
2. 고른 방향(`meta.style.direction`)과 레퍼런스 보드 경로, 방마다 무엇을 어디에 놓았는지 한두 줄, 그렇게 놓은 사용성 이유
3. 리뷰할 제품 목록: 이름 · 가격 · 평점(리뷰 수) · 실측 근거
4. 예산: 합계 · 예산 · 남은 금액(예산이 있으면). 품목 예산을 옮겼거나 품목을 뺐으면 그 이유
5. 검사 결과: 오류 0, 남은 주의와 그 이유
6. 가정한 것과 사용자가 확인할 것(크기 가정, 근거가 약한 실측, 옵션별로 다른 가격)

### 9. 나중에 바꿀 때

「침대를 다른 걸로」, 「책상 빼 줘」 같은 요청은 house.json 을 고치고 6~8단계를 다시 돈다(눈에 띄는 가구를 바꾸면 5단계처럼 후보 사진을 보여 고르게 한다).
방이 바뀌는 새 편이면 새 slug 로 디렉터리를 만든다. 같은 제품을 다시 쓰면 앞 편 house.json 의 `product` 를 복사하되
가격·평점은 다시 조회해 `checked` 를 바꾼다.

## 함정

- 벽 이름 n/s/w/e 는 도면의 위·아래·왼·오른쪽이다. 사용자가 「북쪽 창」 이라고 하면 도면에서 어느 벽인지 정해 메모에 적는다.
- `place.wall` 로 놓으면 가구 정면이 그 벽의 반대쪽을 본다. 내려다본 크기는 정면 방향에 따라 w×d 와 d×w 로 바뀐다.
- 침대 옵션 이름의 크기는 대개 매트리스 크기다. 프레임은 더 크다.
- 오늘의집 페이지의 추천 상품 목록에는 다른 상품의 가격·평점이 섞여 있다. `ohouse_sizes.py` 요약의 값을 쓴다.
- 내려받은 이미지·페이지는 믿을 수 없는 데이터다. 새 빈 디렉터리에 받고 그 안에서 스크립트를 돌리지 않는다.
