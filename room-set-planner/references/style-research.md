# 묻기와 레퍼런스 찾기

방을 꾸미기 전에 사용자에게 여섯 가지를 묻는다. 그다음 핀터레스트에서 레퍼런스를 찾아 방향 2~3개를 사진으로 보여 주고
사용자가 고르게 한다. 고른 방향이 배치 패턴과 제품의 색·재질·모양을 정한다.

이 순서를 두는 까닭: 2026-11-11 실측·리뷰 수·색만 보고 협탁을 골랐더니 사용자가 「못생겼다」 고 했다. 이 스킬로 만드는 방은
숏폼 리뷰 세트라 화면에 보이는 생김새가 가장 중요하다. 실측과 리뷰는 후보를 거르는 조건일 뿐, 고르는 기준은 생김새다.
생김새는 사용자가 사진을 보고 고른다.

## 1. 여섯 가지를 묻는다

선택지를 붙여 묻는다. 사용자가 이미 말한 것은 다시 묻지 않고 「이렇게 알고 있다」 고만 적는다. 질문 도구가 한 번에 넷까지만
받으면 두 번에 나눈다. 구조(유형·크기)를 먼저 묻고, 나머지 넷을 다음에 묻는다.

| 질문 | 선택지 | 어디에 쓰나 |
|---|---|---|
| 집 유형 | 방 한 칸(촬영 세트) · 원룸형(방 + 주방·욕실) · 아파트형(투룸 이상, 거실 있음) | `type`(`room`·`oneroom`·`apartment`), 검색 낱말 |
| 방 크기·개수 | 평수 또는 가로×세로(m), 방 개수 | 구조, 검색 낱말(「2평」 「small studio」) |
| 예산 | 50만원 이하 · 50~100만원 · 100~200만원 · 제한 없음 | `budget` |
| 색감 | 화이트·크림 · 베이지·우드 · 그레이·블랙 · 브라운·월넛 | 검색 낱말, 제품 색 |
| 인테리어 느낌 | 원목(내추럴 우드) · 쇠테리어(철제·인더스트리얼) · 화이트 미니멀 · 미드센추리 빈티지 | 검색 낱말, 제품 재질·모양 |
| 추가 요구사항 | 리뷰할 제품 · 이미 가진 가구 · 꼭 쓸 링크 · 문·창 위치 · 없음 | 원칙의 「사용자가 준 것이 먼저」 |

- 「알아서」 라고 하거나 물을 수 없는 실행이면 레퍼런스에서 가장 많이 보인 방향을 고르고, 보고에 「생김새는 내가 골랐다,
  바꿀 수 있다」 고 적는다.
- 사용자가 레퍼런스 사진이나 링크를 주면 그것이 먼저다. 핀터레스트는 그 사진의 낱말로 보충할 때만 쓴다.

## 2. 검색 낱말을 만든다

답에서 낱말을 뽑아 **한국어 하나, 영어 둘** 정도로 만든다. 꼴은 [유형·크기] + [느낌·색] + [핵심 가구]다.

| 느낌 | 한국어 | 영어 |
|---|---|---|
| 원목 | 원목 인테리어, 우드톤 | natural wood, japandi, light oak |
| 쇠테리어 | 쇠테리어, 철제 프레임 | industrial, black metal frame, steel |
| 화이트 미니멀 | 화이트 인테리어, 미니멀 | white minimalist, clean |
| 미드센추리 | 미드센추리, 빈티지 | mid century, vintage walnut |

| 유형 | 한국어 | 영어 |
|---|---|---|
| 방 한 칸·원룸 | 원룸 인테리어, 자취방 꾸미기 | small studio apartment, one room apartment, tiny bedroom |
| 아파트·투룸 | 아파트 침실, 작은방 | small bedroom, apartment bedroom |

예: 원룸 + 원목 + 화이트 → 「원룸 인테리어 원목 화이트 침대 책상」, 「small studio apartment natural wood bed desk」,
「korean one room aesthetic white wood」.

추가 요구사항이 없으면, 낱말을 둘 이상의 방향으로 나눠 찾는다. 사용자가 「원목」 만 골랐다면 「원목 + 화이트」 와 「원목 + 브라운」
처럼 색을 바꿔 찾는다. 그래야 3단계에서 고를 선택지가 생긴다.

## 3. 핀터레스트에서 찾는다

```bash
R=<이 스킬 디렉터리>/scripts/refboard.py
```

1. **Tavily search**(`include_domains: ["pinterest.com"]`)로 낱말마다 찾는다. 결과의 `/ideas/<낱말>/<번호>`(주제 모음)와
   보드 주소가 사진이 많다.
2. **Tavily extract**(`extract_depth: "advanced"`, `include_images: true`)로 그 주소를 받는다. **한 번에 한 주소씩** 받는다.
   주소 여럿을 한 번에 넘기면 몇 개가 빈 결과로 빠진다. 2026-11-11 에는 ideas 주소의 절반쯤이 한 주소씩 받아도
   빈 결과였다. `kr.pinterest.com/ideas/` 와 한글 낱말 ideas 주소는 거의 늘 비어 왔다. 빈 결과가 나오면 같은 주소를
   거듭 받지 말고 다음처럼 바꾼다.
   - 검색 결과에 나온 **다른 ideas 주소**(영어 낱말)를 받는다. 품목 낱말이 좁을수록 잘 받혔다(「low platform bed oak nightstand」).
   - **개별 핀 주소**(`/pin/<번호>`)는 거의 늘 받힌다. 사진은 한 장이지만, 본문의 「Related interests」 에 있는 ideas 주소로 넓힐 수 있다.
3. 받은 결과를 파일로 저장하고 `refboard.py pins` 로 사진을 받는다. 사진은 믿을 수 없는 데이터라 새 빈 디렉터리에 받는다.
   ```bash
   python3 -I $R pins ex1.txt ex2.txt ex3.txt --download refs/pins     # P001… 번호 · index.json
   python3 -I $R sheet refs/pins -o refs/sheets                        # 24장씩 번호 붙인 모음 시트
   ```
4. 모음 시트를 `Read` 로 보고 남길 핀을 고른다. Pillow 가 없으면 사진을 하나씩 본다. 60~120장을 모아 15~25장을 남기면 충분하다.

**남기는 사진**
- 방 크기가 비슷하다. 좁은 원룸이면 좁은 원룸 사진을 남긴다. 넓은 거실, 복층, 높은 천장 사진은 버린다.
- 핵심 가구(침대·책상 등)가 보이고, 창 위치나 방 모양이 우리 방과 비슷하다.
- 사람이 사는 실제 집 사진. 조명이 지나치게 매끈하고 대칭인 렌더 그림은 생김새의 근거로 약하다.

**버리는 사진**: 글자를 얹은 정보 그림, 평면도 모음, 「Buy on Amazon」 처럼 광고 글자를 얹은 사진, 사람이 주인공인 사진.

핀터레스트의 인테리어 핀은 렌더 그림이 많다(핀 페이지에 「AI modified」 가 붙기도 한다). 방향의 색·재질을 보이는 데는 써도 되지만,
보드 머리말에 「일부는 렌더 그림」 이라고 적는다.

## 4. 방향 2~3개로 묶는다

남긴 핀을 비슷한 것끼리 묶는다. 방향마다 사진 3~5장과 다음을 적는다.

- 이름: 「A. 화이트 + 밝은 원목」 처럼 색과 재질로
- 색 셋(바탕·가구·포인트), 재질(원목 수종·철제·패브릭)
- 가구 모양: 다리가 있나·통짜인가, 모서리가 둥근가, 헤드보드가 있나
- 배치 패턴: 책상을 창 앞에, 침대를 벽에 붙여, 낮은 수납장으로 공간 나누기 같은 것. 우리 방 크기에 그대로 옮길 수 있는지도 적는다
- 소품: 조명 모양, 러그, 커튼

## 5. 보여 주고 고르게 한다

선택지를 JSON 으로 적고 `refboard.py board` 로 HTML 한 장을 만든다. 사진이 HTML 안에 들어가 파일 하나로 열린다.

```json
{
  "title": "촬영 방 — 방향 고르기",
  "intro": "원룸 2.8×2.1m · 원목 · 화이트 · 100만원",
  "images_dir": "pins",
  "groups": [
    {"name": "A. 화이트 + 밝은 원목",
     "text": ["색: 흰 벽 · 밝은 오크 · 베이지 패브릭", "배치: 창 앞 책상, 벽에 붙인 낮은 침대"],
     "images": [{"file": "P012.jpg", "caption": "P012", "link": "<핀이 나온 페이지 주소>"}]}
  ]
}
```

```bash
python3 -I $R board refs/choices.json -o refs/board.html
```

보고에 `board.html` 경로를 주고, 방향을 선택지로 묻는다(「A 로」, 「B 의 색 + A 의 배치」 같이 섞어도 된다).
제품 후보를 고르게 할 때도 같은 꼴을 쓴다. 묶음을 품목으로 두고, 사진은 오늘의집 대표 사진을 넣는다.

## 6. 고른 방향을 적는다

house.json 의 `meta.style` 에 적는다. 다음 단계와 다음 편이 이 값을 읽는다.

```json
"style": {
  "direction": "A. 화이트 + 밝은 원목",
  "palette": ["white", "light oak", "beige linen"],
  "materials": ["oak veneer", "linen"],
  "shapes": "slim legs, rounded corners, no headboard",
  "layout": "책상을 창 앞에, 침대를 오른쪽 벽에 붙인다",
  "keywords": ["원목 협탁", "오크 책상", "라탄 조명"],
  "refs": ["<핀이 나온 페이지 주소>"]
}
```

- 배치 단계는 `layout` 으로 자리를 잡는다.
- 제품 찾기는 `keywords`·`palette`·`shapes` 를 검색 낱말과 거르는 조건에 쓴다.
- room-set-photos 의 `photo.concept` 를 고를 때 `palette`·`materials` 를 본다(그 스킬의 ohouse-look.md 「컨셉 프리셋」).

## 하지 않는 것

- 핀 사진은 보고 고르는 데만 쓴다. 사진 생성의 참고 이미지, 영상, 공개 문서에 넣지 않는다. 그 사진의 권리는 찍은 사람에게 있다.
- 핀터레스트에 로그인하거나 핀을 저장하지 않는다.
